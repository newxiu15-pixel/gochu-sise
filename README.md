# 고추 공판장 시세

서안동농협 고추공판장 시세를 매일 자동으로 모아서, 폰에서 링크 하나로 보는 페이지.

---

## 구동 원리

```
  ① 서안동농협 홈페이지                  ② 농넷(백업)
     고추가격시세 게시판                    서안동 공판장 API
     품종별 최고/최저/평균/물량               품종별 평균가
            │                                    │
            └──────────┬─────────────────────────┘
                       ▼
              ③ GitHub Actions
                 평일 오후 6시·밤 9시 자동 실행
                 collect.py 가 두 곳을 읽어 합침
                       │
                       ▼
              ④ prices.json 파일에 누적
                 (하루치가 아니라 2년치 전체가 한 파일)
                       │
                       ▼
              ⑤ GitHub Pages 가 자동 배포
                       │
                       ▼
              ⑥ 아버지 폰: 링크 클릭 → 오늘 시세
```

**서버가 없다.** 항상 켜둘 컴퓨터도, 데이터베이스도, 월 사용료도 없다.
GitHub이 정해진 시각에 파이썬 스크립트를 잠깐 돌려주고, 결과 파일을 웹에 올려둘 뿐이다.

**화면은 HTML 파일 한 장이다.** 그래프까지 직접 그리기 때문에 외부 라이브러리를 하나도 쓰지 않는다.
폰이 받는 것은 HTML 한 개와 데이터 파일 한 개, 끝이다.

### 단계별로 무슨 일이 일어나나

| 단계 | 하는 일 | 걸리는 시간 |
|---|---|---|
| ① 게시판 읽기 | 최근 20 경매일 글을 열어 표를 읽는다 | 약 20초 |
| ② 백업 읽기 | 농넷에서 최근 45일 평균가를 받는다 | 1초 |
| ③ 합치기 | 게시판 값을 우선하고, 빠진 날만 백업으로 메운다 | 즉시 |
| ④ 저장 | 새 날짜만 파일에 추가하고 커밋한다 | 2초 |
| ⑤ 배포 | GitHub이 알아서 새 화면을 올린다 | 30초 |

전체 1분 안에 끝난다.

---

## 유지보수

### 손댈 일이 없게 만든 것

**라이브러리를 안 쓴다.**
화면에 쓰인 외부 라이브러리가 0개다. 그래프도 직접 그린다.
버전이 바뀌어 깨질 일도, CDN이 죽어 화면이 빌 일도 없다.
파이썬 쪽도 `requests`와 `beautifulsoup4` 둘뿐이다. 둘 다 십 년 넘게 쓰이는 것들이다.

**데이터베이스가 없다.**
2년치 시세가 500KB짜리 JSON 파일 하나다. 백업이 필요하면 파일을 복사하면 된다.

**서버가 없다.**
꺼질 것도, 디스크가 찰 것도, 요금이 나갈 것도 없다.

**읽는 곳이 두 군데다.**
서안동 게시판이 주 소스, 농넷 API가 백업이다.
게시판이 안 열려도 농넷에서 평균가는 들어온다. 그래프도 판단 문구도 계속 나온다.

### 문제가 생기면 아버지 화면에 바로 뜬다

아버지는 프로그램이 고장났는지 알 방법이 없다.
그래서 이상이 생기면 **화면 맨 위에 빨간 경고**가 뜨고, 아들에게 알리라는 문구가 같이 나온다.

| 상황 | 화면에 뜨는 것 |
|---|---|
| 정상 | (경고 없음) 날짜 아래 회색으로 `자동 확인 정상 · 오늘 21:22 확인함` |
| 두 경로 모두 실패 | 🔴 **오류 발생 — 프로그램 수정이 필요합니다** / 이 화면을 아들에게 보여주세요 |
| 자동 실행이 멈춤 (평일 이틀 이상) | 🔴 **오류 발생 — 자동 확인이 멈췄습니다** / 마지막 확인 날짜 표시 |
| 게시판만 깨져 백업으로 버티는 중 | 🔴 **일부 오류 — 프로그램 수정이 필요합니다** / 평균가만 나온다고 안내 |
| 새 시세가 사흘 넘게 안 올라옴 | 🟡 새 시세가 안 올라오고 있습니다 / 공휴일이면 정상이라고 안내 |
| 인터넷이 끊김 | 🔴 시세를 불러오지 못했습니다 / 새로고침 안내 |

**매일 확인이 돌았다는 사실 자체를 화면에 남긴다.**
주말처럼 새 시세가 없는 날에도 확인 기록은 갱신되므로, 화면의 `오늘 확인함`을 보면
프로그램이 살아 있다는 것을 아버지가 직접 알 수 있다.

즉 조용히 옛날 값을 새 값인 척 보여주는 일은 없다.

### 깨질 수 있는 곳은 딱 하나

**서안동농협이 홈페이지를 개편해서 시세표 모양이 바뀌는 경우.**

그때 어떻게 되나

1. 게시판 파싱이 실패한다
2. 농넷 백업이 대신 들어온다 → **화면은 계속 돌아간다** (최고·최저가만 빈칸)
3. 아버지 화면에 `일부 오류 — 프로그램 수정이 필요합니다` 빨간 경고가 뜬다
4. GitHub Actions가 실패로 표시되고, 알림을 켜뒀다면 메일이 온다

**고칠 곳은 `sources/seoandong.py` 파일 하나, 그중에서도 `parse_post()` 함수 하나다.**
표에서 어느 칸이 최고가인지만 다시 맞춰주면 끝난다. 30줄짜리 함수다.

고친 뒤에는 검증 스크립트를 돌려 확인한다.

```bash
python collect.py       # 수집이 되는지
node test_screen.js     # 값·그래프·경고가 제대로 나오는지
```

`test_screen.js`는 실제 데이터로 화면 로직을 전부 훑고, 오류 경고 다섯 가지 상황을
시뮬레이션해 문구가 맞게 뜨는지까지 확인한다.

### 실패를 메일로 받고 싶다면

GitHub 계정 설정에서 Actions 실패 알림을 켜두면 된다.
`Settings → Notifications → Actions → Failed workflows only`

수집이 실패한 날만 메일이 온다. 평소에는 조용하다.

### 확인하고 싶을 때

```bash
python collect.py          # 지금 바로 수집해 본다
```

화면에 이렇게 찍힌다.

```
게시판: 20일치
농넷 백업: 30일치
수집 완료: 새로 1일 추가. 최신 2026-07-27
```

`게시판 실패`라고 뜨면 그때 손보면 된다.

## 새 공판장 붙이기

안동·영양 등 다른 공판장 시세를 나중에 찾으면, `sources/` 폴더에 파일 하나만 추가한다.

```python
MARKET_ID = "yeongyang"
MARKET_NAME = "영양 고추공판장"

def collect():
    return {"2026-09-01": {"화건": {"high": 0, "low": 0, "avg": 0, "volume": 0, "unit": "근"}}}
```

`collect.py`에서 한 줄 부르면 화면에 공판장 선택이 생긴다.

## 파일 구조

```
collect.py                   수집 실행. 이것만 돌리면 된다
sources/
  seoandong.py               서안동 게시판 파서 ← 고칠 일이 있다면 여기
  seoandong_backup.py        농넷 API 백업 경로
data/prices.json             2년치 시세 원본
docs/
  index.html                 화면 전체 (HTML+CSS+JS 한 파일)
  prices.json                화면이 읽는 데이터 사본
.github/workflows/collect.yml  매일 자동 실행 설정
```
